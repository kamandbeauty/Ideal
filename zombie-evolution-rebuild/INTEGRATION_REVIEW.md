# Review of the root prototypes

The active project is `zombie-evolution-rebuild`. The repository root contains a self-contained Godot prototype (`project.godot`, `scenes/main.tscn`, `scripts/main.gd`, and `tests/game_logic_test.gd`) and `zombie-evolution/` contains another independent prototype. Their own `res://` paths are relative to their own project roots. They are not drop-in files for the active project: both use a different main scene, gameplay structures and APIs. Replacing the active project's files would change functioning gameplay and invalidate existing validation.

The three bundled DejaVu Sans font files have the same SHA-256. The active project already contains the font and its license, so no duplicate is needed. The older scripts include different enemy, audio, boss, power-up and progression implementations, none of which has been established to be compatible with the active scene. These were not silently ported or presented as tested features. The older Android preset is also not a replacement for the verified active preset. The independent files and the root README have been left untouched.

Useful edge-case ideas from `tests/game_logic_test.gd` and `zombie-evolution/tests/rules_test.gd` are adapted in `tests/imported_gate_edge_test.gd`, using the active level and its real gate implementation: doubling includes the hero, the squad cap is enforced, Persian digits handle zero and multiple digits, and gate selection/crossing applies at most once. This adds a headless check without removing or weakening the existing 11 checks. It does not add the older prototypes' unimplemented gate effects or change gameplay.

Initial static review: grammar parsing of the root and `zombie-evolution/` GDScript files succeeded, and a scan of their literal `res://` references found no missing files. These checks do not establish runtime compatibility, gameplay correctness or Persian visual rendering. For the new test, grammar parsing, shell syntax, workflow YAML parsing, and the current source-manifest check passed locally. Runtime results must be taken from a fresh CI run; a Godot executable is not available locally.

## Uploaded starter-kit scripts

Commit `1525854c2bf26c685ee243407d972412ab87673b` added `Player.gd`, `Squad.gd`, `MathGate.gd`, `Zombie.gd`, `GameManager.gd`, `HUD.gd`, and a README at the repository root. All six scripts passed `gdparse` grammar parsing; this is not Godot engine or integration validation. They describe a scene-wired starter kit with numerous unassigned node paths, scenes and TODOs, not the active project's node structure.

- `Player.gd` moves in negative Z and invokes `take_damage`; the active level runs in positive Z and uses `apply_damage` and its own collision/raycast flow. Replacing it would break existing play.
- `Squad.gd` needs a separate soldier scene and counts only soldiers when multiplying; the active project counts the hero for the double gate. It also reports requested recruits even when the soldier scene is absent.
- `MathGate.gd` selects by player entering an Area3D, whereas the active gate is selected by shooting before crossing. Its firepower effect expects `apply_firepower_modifier`, which the supplied `Player.gd` does not implement.
- `Zombie.gd` expects separate group membership and `take_damage`; active actors use different signals, collision and damage APIs. `GameManager.gd` depends on unassigned scenes/spawn points, uses timed placeholder waves, and requires an external boss; its completion would not be wired by copying the script.
- `HUD.gd` needs assigned editor-created controls and a separate theme/font, while the active HUD constructs its controls and already loads a bundled Persian-capable font. Its Persian-digit conversion is already supported by the active HUD; the added edge-case test exercises equivalent behavior. The uploaded README describes the starter kit rather than the validated build and cannot replace the active project's documentation.

The useful single-use gate and Persian-number behavior is covered against the actual active project by `imported_gate_edge_test.gd`. Unsupported or incompatible implementations have not been wired into gameplay or moved over existing files. The uploaded originals remain at the root as committed by the user, and the pre-existing local root README edit remains unchanged. Further feature integration requires designing and testing against the active scene rather than copying this starter kit as-is.
