Because `BusinessData` reaches into 18 files including the whole UI, the plan
**does not delete Roadstop code** while the guild is being built. New modules live
under `scripts/guild/**` and `scenes/guild/**` and never import the road classes;
the Roadstop tree is removed in one commit once the guild slice is playable and its
own tests/screenshots exist. This keeps CI green in every intermediate commit.

## 4. Test infrastructure

* `tests/run_tests.gd` — headless `SceneTree`, 10 suites, 300+ checks, writes
  `documentation/qa/test-results.json`, exits non-zero on failure.
* Suites worth keeping as patterns: `test_economy` (numbers), `test_save`
  (round trip, corruption, clamping), `test_profile` (multi-container state),
  `test_daily_and_tips` (curves and anti-farm rules).
* CI (`ci.yml`): import → tests → xvfb play-through with screenshots → publish
  previews → boot main scene. `apk.yml`: template + SDK + export + APK inspect +
  release upload.
* Verification loop that actually caught real bugs this project has already paid
  for: lint (`gdlint`), parse, CI screenshots, and the Android build.

New suites planned for Guild Tycoon: `test_items`, `test_warehouse`,
`test_carry`, `test_orders`, `test_treasury`, `test_adventurers`,
`test_missions_sim`, `test_guild_save`. All logic stays in `RefCounted` classes so
they run without a renderer — the single most important architectural rule carried
over from Roadstop.

## 5. Asset audit — what exists versus what Guild Tycoon needs

Existing: 16 Kenney GLBs (garage, 4 small buildings, grass/trees, pavement,
roads), one 512² palette atlas + a repainted retro atlas, Vazirmatn fonts, 19 OGG
audio files, generated icon set.

| Need (brief) | Available today | Gap |
| --- | --- | --- |
| Anime/manhwa characters, expressive faces | box rig (`person_mesh.gd`) | **Large** — no character mesh, no facial rig, no animation clips |
| Detailed outfits, classes (Warrior/Mage/…) | colour palettes only | **Large** |
| Fantasy hall architecture (wood, stone, banners, shelves) | Kenney city kit (modern) | **Large** — needs a new modular kit |
| Character animations (idle/walk/run/pickup/carry/deliver/deposit) | procedural pivots | **Medium** — procedural poses are acceptable for the slice, not for "premium" |
| Magical effects, cinematic lighting | emissive materials, one omni per plot | **Medium** |
| Icons, portraits, UI art | none | **Can be generated** (see plan) |

**Environment constraint that shapes the plan:** this workspace can only reach
`github.com`, `codeload.github.com`, `api.github.com`, `registry.npmjs.org`,
`pypi.org` and `files.pythonhosted.org`. Asset marketplaces (Sketchfab, Mixamo,
Kenney's own site, itch.io) are **not reachable**, and no asset can be purchased
from here. Therefore the realistic Phase 1 output is:

1. **Environment:** detailed *procedural* geometry with a shared material set
   (wood, stone, metal, cloth, magic emissive), built from a modular kit generated
   by a committed script, documented as replaceable by real GLBs.
2. **Characters:** a proportioned, multi-part rig with a cel-palette material and
   procedural animation, behind a `GuildCharacter` interface so a real glTF +
   `AnimationTree` can replace it without touching gameplay code.
3. **Presentation polish that is actually deliverable here:** generated 2D art for
   portraits, class icons, item icons, banners and the UI frame; strong lighting,
   fog, vignette and colour grading. This is where the "premium manhwa" *feel* can
   genuinely come from in Phase 1.

If the target is literal "premium manhwa 3D", the project needs external assets;
the plan specifies the exact drop-in contract so that swapping them later is a data
change, not a rewrite.

## 6. Technical risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| `gl_compatibility` has no `diffuse_toon`; toon shading is limited | Visual identity | Ramps baked into albedo + rim/emissive + custom `light()` shader, verified by CI screenshot before it is adopted. Fallback: stylised PBR with strong palette. |
| No character animation clips | Brief asks for 8 animations | Procedural pose blending on the rig; `AnimationTree` slot ready for real clips. |
| Navmesh baking in CI | NPCs walking into furniture | Hand-authored `NavigationRegion3D` polygons for one hall (deterministic, commit-able), plus `NavigationAgent3D` avoidance. |
| Carry/delivery logic drifting from inventory | The very thing the slice must prove | All stack state lives in `Inventory`/`CarryStack` RefCounted classes with unit tests; the 3D stack is a *view* of the count (1 mesh per unit, pooled). |
| Draw calls on mobile | 60 FPS target | Kit is merged by material; NPCs pooled; max 6 dynamic lights; MSAA off; 3 quality presets. |
| Two games in one project during the transition | Build size, confusion | Roadstop stays but is excluded from the guild export via `exclude_filter`; removed in the last phase. |
