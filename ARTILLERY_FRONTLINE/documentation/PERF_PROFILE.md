# گزارش پروفایل کارایی — ARTILLERY FRONTLINE

الگوی این سند از ایدهٔ `perf-profile` در [Claude-Code-Game-Studios](https://github.com/donchitos/claude-code-game-studios) (MIT) گرفته شده. هیچ hook یا مجوز bash اضافه نشده است.

## قاعدهٔ اصلی: داده‌ای نیست، یعنی ارزیابی نشده

اگر ورودی یک بخش موجود نیست، آن بخش **`NOT ASSESSED — NO DATA`** است. عدد تخمینی نمی‌گذاریم و عدد یک بخش را برای بخش دیگر استفاده نمی‌کنیم. `NOT ASSESSED` یک نتیجهٔ درست است، نه شکست.

## ۱. ورودی‌ها و وضعیت آن‌ها

| ورودی | منبع | وضعیت (FOUND / ABSENT) |
|---|---|---|
| smoke بازی، رندر نرم‌افزاری | `documentation/qa/smoke-report.json` (فیلد `performance`) | |
| smoke ساحلی، رندر نرم‌افزاری | `documentation/qa/coastal-smoke-report.json` (فیلد `performance`) | |
| گیرکردن و jank روی دستگاه واقعی | خروجی `adb shell dumpsys gfxinfo` طبق `DEVICE_QA.md` | |
| دمای دستگاه | خروجی `adb shell dumpsys thermalservice` | |
| ذخیرهٔ پروفایل CPU/GPU | Android Studio Profiler یا Perfetto | |

## ۲. بودجه‌ها

این بودجه‌ها هدف‌های ما برای مرحله‌های بعد هستند، نه ادعای عملکرد فعلی:

| شاخص | مقدار فعلی (CI، llvmpipe، فقط دسکتاپ) | بودجه پیشنهادی برای دستگاه |
|---|---|---|
| فریم (ms) در smoke بازی | ≈۵۳٫۸ ms (≈۱۸٫۶ FPS) | ≤ ۳۳٫۳ ms در ۹۵٪ زمان نبرد |
| فریم (ms) در smoke ساحلی | ≈۷۲٫۲ ms (≈۱۳٫۹ FPS) | ≤ ۳۳٫۳ ms در ۹۵٪ زمان نبرد |
| draw call (ساحلی) | ۳۱۱ | باید روی دستگاه اندازه‌گیری شود |
| دما بعد از ۱۰ دقیقه | NOT ASSESSED | باید روی دستگاه اندازه‌گیری شود |

**یادآوری:** عددهای llvmpipe فقط کف نرم‌افزاری دسکتاپ هستند. آن‌ها عملکرد GPU موبایل، حرارت یا 30/60 FPS پایدار را ثابت نمی‌کنند.

## ۳. گزارش گیرکردن (jank)

برای هر نبرد یک ردیف ثبت کنید:

| تاریخ | مدل دستگاه | GPU | کیفیت بازی | مدت نبرد | Janky frames (%) | 95th / 99th (ms) | دمای پایان | زمان گیرکردن (ثانیه) | مدرک |
|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | |

قوانین:
- ریست آمار قبل از هر نبرد: `adb shell dumpsys gfxinfo com.frontline.artillery reset`.
- حداقل یک نبرد ۱۰ دقیقه‌ای در «خودکار» و یک بار در «بالا».
- اگر گیرکردن ثبت شد، زمان دقیق و ویدیو را ضمیمه کنید؛ توضیح کلی کافی نیست.

## ۴. آنچه از این گزارش برنمی‌آید

- عدد FPS دسکتاپ را نباید به‌عنوان عملکرد موبایل گزارش کرد.
- علت گیرکردن تا زمانی که با پروفایل روی دستگاه تأیید نشود، «ثابت‌شده» نیست. تغییرات کد فعلی (کاهش تعویض کیفیت حین نبرد و ساخت دوبارهٔ بافت نویز) بر اساس بررسی کد بودند، نه اندازه‌گیری.
- ساخت ragdoll هنگام مرگ سرباز و بارگذاری مدل‌ها در هر spawn هنوز اندازه‌گیری نشده‌اند.
