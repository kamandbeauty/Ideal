# راهنمای QA دستگاه واقعی — ARTILLERY FRONTLINE

این سند برای اجرای آزمون روی گوشی واقعی (Mali و Adreno) و در صورت امکان شبیه‌ساز Android نوشته شده. **تا این سند پر و امضا نشود، هیچ ادعای اجرای اندروید یا کارایی موبایل مجاز نیست.**

## ۱. وضعیت این سند

- این سند در محیط CI/ساندباکس نوشته شده؛ هیچ گوشی یا شبیه‌ساز در آن اجرا نشده است.
- شبیه‌ساز رسمی Google (Android Emulator و system image) از `dl.google.com` دانلود می‌شود و در محیط CI فعلی دسترسی ندارد. این آزمون باید روی ماشین توسعه‌دهنده یا دستگاه واقعی انجام شود.
- بسته ARM64 فقط روی دستگاه ARM64 یا شبیه‌ساز با ترجمهٔ ARM اجرا می‌شود. APK آزمایشی `Artillery-Frontline-qa-x86_64.apk` فقط artifact CI است و برای شبیه‌ساز x86_64 ساخته می‌شود.

## ۲. نصب

```sh
adb devices                                   # دستگاه باید "device" باشد
adb install -r delivery/Artillery-Frontline-arm64.apk
adb shell pm list packages | grep frontline   # انتظار: com.frontline.artillery
```

برای شبیه‌ساز x86_64 (فقط با APK آزمایشی CI):

```sh
adb install -r Artillery-Frontline-qa-x86_64.apk
```

## ۵. اندازه‌گیری گیرکردن و کارایی

هدف: پیدا کردن lagهای مرحله‌ای. این اعداد مربوط به همان گوشی هستند و به دستگاه‌های دیگر قابل تعمیم نیستند.

```sh
# ریست شمارنده‌های فریم قبل از شروع یک نبرد ۱۰ دقیقه‌ای
adb shell dumpsys gfxinfo com.frontline.artillery reset
# بعد از نبرد
adb shell dumpsys gfxinfo com.frontline.artillery | grep -E "Janky frames|50th|90th|95th|99th"
# لاگ موتور و خطاها
adb logcat -d | grep -iE "godot|script error|shader|crash" > logs-godot.txt
# دما
adb shell dumpsys thermalservice | head -40
```

ثبت کنید: تعداد frame jank، درصد frame بالای ۱۶٫۷ میلی‌ثانیه، و زمان گیرکردن (با ساعت یا ویدیو). یک نبرد کامل حداقل ۱۰ دقیقه باشد و یک بار هم در کیفیت «خودکار» و یک بار در «بالا» اجرا شود.

## ۶. ابزار و گزارش

- ویدیوی ۱۰ دقیقه‌ای از نبرد با گوشی روی حالت landscape ضبط کنید.
- خروجی‌های `gfxinfo`، `logcat` و `thermalservice` را در `documentation/qa/device/` ذخیره کنید (این پوشه را خودتان بسازید).
- نتیجه را با تاریخ، مدل دستگاه و شمارهٔ commit بسته بنویسید.

## ۷. معیار قبولی

- هیچ crash در ۱۱ آزمون عملکردی.
- ذخیرهٔ پیشرفت بعد از force-stop باید بماند.
- اگر jank یا دما بالا بود، به‌جای ادعای کارایی، عدد دقیق ثبت شود.
- در گزارش نهایی، حتماً «روی دستگاه واقعی اجرا شد» فقط وقتی نوشته شود که این فرم پر شده باشد.
