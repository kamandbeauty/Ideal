## نسخهٔ کوتاه (اگر ابزارت محدودیتِ طول دارد، این را بده و بخش‌های ۶ تا ۸ را ضمیمه کن)

> یک اپ اندرویدِ Kotlin بساز که فیلمِ عمودیِ ۱۰۸۰×۱۹۲۰@۳۰fps از «متنِ فارسی + صدای گوینده + تصاویر» تولید کند، دقیقاً مثل موتورِ `motion/rowling-potter` این ریپو.
> ۱) متن را به خط‌های زیرنویس بشکن (بدون تغییرِ کلمه). ۲) با whisper.cpp/Vosk ریتمِ کلمه‌ها را بگیر و متن را با هم‌ترازیِ DP (پارامترها: SKIP_A=.20، SKIP_S=.30، BASE=.34) روی صدا قفل کن؛ خروجی `words[]{line,word,start,end}` و `sentences[]{start,end,hold}` با `duration = voDuration+1.1`. ۳) تصاویر را به ۱۶۰۰×۲۸۴۵ برسان و گریدِ گاما/اشباع ۱٫۱۴/کنتراست ۱٫۰۶ بزن. ۴) با OpenGL ES فریم‌به‌فریم رندر کن و مستقیم به `MediaCodec` input surface بده (H.264 High، ۳٫۳Mbps، GOP ۱s) + AAC ۱۹۲k ۴۸k استریو با `MediaMuxer`.
> استایل: زیرنویسِ کلمه‌به‌کلمه با Vazirmatn 700/۵۸px در `bottom=470px`، کلمهٔ فعال `#ffd79a` و scale ۱٫۰۵۵، محو شدن ۰٫۱۷s با blur ۵→۰؛ لوگو ۱۹۰px، شفافیت ۰٫۳۰، `bottom=196px`، بدونِ قاب؛ بدونِ گرید تیره/وینیت؛ دیزالو ۰٫۵s بین پلیت‌ها.
> دوربین: برای هر صحنه (چند زیرنویسِ روی یک پلیت) یک مسیرِ پیوسته: `legs=clamp(dur/5.2,1,3.4)`، زومِ این/اوت + پنِ آرام + رانشِ یک‌طرفه + لرزشِ نرم؛ **حرکت هرگز در مرزِ زیرنویس ریست نشود**. فرمولِ کامل و مقادیرِ تستِ طلایی در بخش ۶٫۳ و ۶٫۴.
> خروجی در گالری + اشتراک. رندر باید قابلِ ادامه باشد (قطعه‌های ۹۰۰ فریمی) و همین فایل مرجع را بیت‌به‌بیت بازتولید کند (SSIM ≥ ۰٫۹۵).

## ۰. نقش و مأموریت

تو یک مهندس ارشد اندروید هستی. مأموریتت ساختِ یک اپ اندرویدِ بومی (Kotlin) است که **دقیقاً همان کاری را روی گوشی انجام دهد** که ریپوی `kamandbeauty/Ideal` با Node + Playwright + ffmpeg انجام می‌دهد: از یک «متنِ فارسی + یک فایلِ صدای گوینده + مجموعه‌ای تصویر» یک فیلمِ عمودیِ ۹:۱۶ با زیرنویسِ کلمه‌به‌کلمه، دوربینِ متحرک، لوگوی نیمه‌شفاف و کارت پایانی بسازد و MP4 بدهد.

کلمهٔ کلیدی: **exactly**. نه «شبیه»، نه «الهام‌گرفته». اعدادِ پیکسلی، فرمول‌های دوربین، منحنی‌های نرم‌سازی و زمان‌بندی‌ها در بخش‌های ۵ تا ۸ با دقتِ عددی آمده‌اند و باید بی‌کم‌وکاست پیاده شوند. اگر جایی مجبور به ساده‌سازی شدی، همان عدد را نگه دار و فقط پیاده‌سازیِ فنی را عوض کن.

خروجیِ تو در پایان: یک اپِ قابلِ نصب که با ورودی‌های نمونه، ویدیویی می‌سازد که با فریم‌های فیلمِ مرجع قابلِ قیاس باشد (SSIM ≥ ۰٫۹۵ و انحرافِ زمانیِ کلمه‌ها ≤ ۵۰ms میانه).

## ۲. پایپ‌لاین (۷ مرحله؛ هر مرحله در اپ یک ماژول است)

1. **متن** — متنِ فارسی، جمله‌به‌جمله؛ فقط شکستنِ خط، هیچ کلمه‌ای عوض نمی‌شود.
2. **صدا** — فایلِ VO کاربر (wav/m4a/mp3) → دیکد به ۴۸k مونو float → مدت و کانتور.
3. **هم‌ترازی** — ASR فقط برای «ریتم»؛ متنِ کاربر با DP روی کلمه‌های شنیده‌شده قفل می‌شود → `WORDS[]` و `SENTENCES[]`.
4. **تصاویر** — ۳۲ پلیت (یا هر تعداد) + پیش‌پردازشِ پیکسلی (بخش ۶).
5. **چیدمان** — نگاشتِ «خطِ زیرنویس → پلیت» (`SCENE_OF`) و پارامترهای دوربینِ هر صحنه.
6. **رندر** — هر فریم از روی شمارهٔ فریم ساخته می‌شود (`seek(frame)`)، پس رندر قطعی (deterministic) و قابلِ ادامه است.
7. **کدگذاری** — H.264 + AAC + mux.

اصلِ طلاییِ موتور: **هیچ انیمیشنی با زمانِ واقعی اجرا نمی‌شود.** همه‌چیز تابعی است از `frame` و `t = frame / 30`. هیچ `Random`، هیچ تاریخِ سیستم، هیچ شبکه. دو بار رندر از یک پروژه باید بیت‌به‌بیت یکسان باشد.

## ۴. زمان‌بندیِ کلمه‌به‌کلمه (سخت‌ترین و مهم‌ترین بخش)

معیارِ پذیرشِ کاربر: «زیرنویس کاملاً هماهنگ با صدا». پیاده‌سازیِ مرجع در `tools/word-timing.py` است؛ این‌ها را عیناً پورت کن.

### ۴٫۱ استخراج ریتم (ASR)

- موتور پیشنهادی: **whisper.cpp** با مدلِ `ggml-base` چندزبانه (q5_1، ~۱۵۰MB، داخل APK یا دانلودِ اولیه) روی CPU با ۴ ترد، یا **Vosk-fa**.
- ورودی: VO دیکدشده به ۱۶kHz مونو PCM.
- گزینهٔ ابری (اختیاری، اگر کاربر آن را روشن کند): Whisper API با `word_timestamps`.
- خروجی: لیستِ `(start, end, word)` فقط برای **ریتم**. متنِ ASR دور ریخته می‌شود (نویزی است).

### ۴٫۲ نرمال‌سازیِ متن برای تطبیق

```
ي→ی  ك→ک  ﻻ→لا
حذفِ اعراب U+064B..U+0652 و کشیده U+0640
حذفِ ZWNJ U+200C و U+200F
أ/إ/آ→ا، ة→ه
حذفِ هر نویسهٔ غیرِ حرف/رقم
```

### ۴٫۳ شباهت

```
bigrams(w) = مجموعهٔ همهٔ دوتایی‌های مجاور (اگر طول<۲ → خودِ کلمه)
dice = 2·|A∩B| / (|A|+|B|)
same = تعداد نویسه‌های هم‌جای برابر / max(len)
sim  = 0.68·dice + 0.32·same        // 0.0..1.0
```

### ۴٫۴ هم‌ترازیِ ترتیبی (DP)

`NS` = تعداد کلمه‌های متنِ ما، `NA` = تعداد کلمه‌های شنیده‌شده.

```kotlin
const val SKIP_A = 0.20   // جا انداختنِ یک کلمهٔ شنیده‌شده
const val SKIP_S = 0.30   // جا انداختنِ یک کلمهٔ متنِ ما
const val BASE   = 0.34   // هزینهٔ پایهٔ هر تطبیق
// dp[i][j] = بهترین امتیاز برای i کلمهٔ متن و j کلمهٔ شنیده‌شده
// move 1 = تطبیق (sim - BASE)، move 2 = حذف از شنیده ( -SKIP_A )، move 3 = حذف از متن ( -SKIP_S )
```

بازسازیِ مسیر از انتها به ابتدا → `anchors: Map<scriptIndex, (start,end)>`.

### ۴٫۵ پرکردنِ شکاف‌ها

- بین دو لنگرِ `i0` و `i1` (اگر `i1-i0>1`): بازهٔ `[anchor[i0].end , anchor[i1].start]` به نسبتِ **طولِ کلمه** تقسیم می‌شود.
- پیش از اولین لنگر: `start = max(0, firstStart − 0.14·firstIndex)` و گامِ یکنواخت.
- پس از آخرین لنگر: گامِ ثابتِ ۰٫۲۰ ثانیه.

### ۴٫۶ یکنواخت‌سازی و مرزِ همسایه‌ها

```
MIN_W = 0.10
a = max(a, prevEnd)؛  b = max(b, a + MIN_W)
برای هر جفتِ همسایه در یک جمله:
  اگر هم‌پوشانی: مرز را وسط ببر
  اگر gap < 0.55s : end[i] = start[i+1]      (چسبیدن)
  اگر gap < 1.30s : end[i] = end[i] + 0.55·gap، start[i+1] = end[i]
```

> منطق: کلمهٔ روشن باید **تا لحظهٔ شروع کلمهٔ بعد** روشن بماند؛ هیچ‌وقت «پرشِ خالی» نباید دیده شود.

### ۴٫۷ مرزِ جمله‌ها و فیلم

```
LEAD = 0.08                         // جمله کمی قبل از اولین کلمه ظاهر می‌شود
sentStart[i] = max(0, firstWordStart − LEAD)
sentEnd[i]   = start[i+1]           // پیوسته، بدونِ شکاف
sentEnd[last] = voDuration + 1.1    // TAIL
hold[i] = min(sentEnd[i], lastWordEnd_i + 0.42)
duration = voDuration + 1.1
frames   = round(duration * 30)
```

### ۴٫۸ کش و کنترلِ دستی (الزامی برای UX)

- نتیجهٔ ASR در `cache/asr-<hash(vo)>.json` کش شود؛ رندرِ دوم بدونِ ASR.
- صفحهٔ «هم‌ترازی»: موجِ صدا + تیکِ هر کلمه، جابه‌جاییِ یک کلمه با درگ، دکمهٔ «قفل روی صدا» و «بازگشت به خودکار».
- نشانگرِ خطا: هر کلمه‌ای که `end-start > 1.2s` یا `< 0.08s` با رنگِ هشدار.

### ۴٫۹ تستِ پذیرشِ هم‌ترازی

روی پروژهٔ مرجع: میانهٔ |Δ| نسبت به `content/words.js` باید ≤ ۵۰ms و صدکِ ۹۵ ≤ ۱۲۰ms باشد.

## ۶. موتورِ رندر — دقیق

### ۶٫۱ استیج

```
Canvas 1080×1920، پس‌زمینه #07080c، overflow hidden.
ترتیبِ لایه‌ها (پایین→بالا):
 1) پلیت B (پلیتِ قبلی، در طولِ گذار)
 2) پلیت A (پلیتِ جاری، با ترنسفورمِ دوربین)
 3) leak   (screen)      4) fog              5) warm (screen)   6) boil (soft-light)
 7) dust (۲۶ ذره)        8) grain (overlay)  9) flash
10) endcard (فقط از endCardStart)
11) subscrim (رادیالِ موضعیِ زیر زیرنویس)
12) logo                13) subtitle
```

اگر تصویری لود نشد: گرادیانِ جانشین `180deg #7d8fa8 → #6f7d94 40% → #4a4459 70% → #241f2c`.

### ۶٫۲ پلیت و گذار

- پلیت با `object-fit: cover` و ترتیبِ ترنسفورم:
  `translate(center) → translate(tx,ty) → rotate(rot) → scale(k)`، مبدأ = مرکزِ کادر.
- **پلیت فقط با تغییرِ صحنه عوض می‌شود، نه با تغییرِ جمله.** چند جمله روی یک پلیت، یک حرکتِ پیوسته دارند.
- گذار: `DISSOLVE = 0.50s`؛ `dp = (t − sceneT0)/0.50`.
  - پلیتِ قبلی با دوربینِ **فریزشده در پایانِ صحنهٔ خودش** (`p=1`) زیر می‌ماند.
  - `opacity(A) = smoothstep5(dp)` (همان `smooth` پایین).
  - افتِ روشنایی وسطِ گذار: `brightness(1 − 0.22·sin(π·dp))` روی کلِ بستهٔ پلیت‌ها.
- `smooth(p) = p³(6p²−15p+10)` روی `[0,1]` (easeInOutQuint). این تابع همه‌جا مرجع است.

### ۶٫۳ دوربین — فرمولِ کامل (همین اعداد)

```kotlin
fun clamp(v: Float, a: Float, b: Float) = min(b, max(a, v))

// پریستِ حرکت (k0,k1 بر پایهٔ amt = 0.0..1.0)
// in    : 1.10 → 1.30+0.20a      out  : 1.30+0.20a → 1.10
// panR/L: 1.26+0.10a (ثابت)      tiltU/D: 1.32+0.10a (ثابت)
// inL/inR:1.12 → 1.34+0.18a      hold : 1.16 → 1.20+0.06a
// hook  : 1.70 → 1.24+0.08a

fun cameraAt(sc: Scene, t: Float, pRaw: Float, seed: Int, dur: Float = 8f): Cam {
    val (k0, k1) = preset(sc.move, sc.amt)
    val a0 = sc.a0; val a1 = sc.a1
    val p  = smooth(pRaw)                      // p خام همان پیشرفتِ صحنه است
    val legs = clamp(dur / 5.2f, 1f, 3.4f)     // هر ~۵ ثانیه یک مرحلهٔ حرکت
    val ph   = seed * 1.9f

    // ۱) زوم: رمپِ پایه + «تنفسِ» پیوسته (برای صحنهٔ بلند چند بار این/اوت)
    var k = k0 + (k1 - k0) * p
    val zoomCycles = max(0f, legs - 1f)
    if (zoomCycles > 0f) {
        val zoomAmp = 0.085f * clamp((dur - 5f) / 7f, 0f, 1f) * (1f + 0.18f * (zoomCycles - 1f))
        k *= 1f + zoomAmp * sin(2f * PI * zoomCycles * p + ph * 0.7f)
    }
    k = clamp(k, 1.04f, 1.85f)

    // ۲) پن: مسیرِ اصلی + چرخشِ آرام + رانشِ یک‌طرفه (تصویر «می‌رود»)
    val sway    = max(1f, zoomCycles)
    val panAmp  = 0.028f + 0.014f * clamp(legs - 1f, 0f, 2f)
    val travel  = 0.030f * clamp(legs - 1f, 0f, 2f) * (p - 0.5f)
    val ax = 0.5f + (a0.x - 0.5f) + ((a1.x - a0.x) * 1.2f) * p + travel
             + panAmp * sin(2f * PI * sway * p + ph)
    val ay = 0.5f + (a0.y - 0.5f) + ((a1.y - a0.y) * 1.2f) * p
             + panAmp * 0.75f * cos(2f * PI * sway * p + ph * 1.4f)

    val maxX = (k - 1f) * 1080f / 2f
    val maxY = (k - 1f) * 1920f / 2f
    var tx = clamp((0.5f - ax) * 1080f * k, -maxX, maxX)
    var ty = clamp((0.5f - ay) * 1920f * k, -maxY, maxY)

    // ۳) لرزشِ خیلی نرم (دو موجِ ناهماهنگ) + تنفس + رول
    val phw = seed * 2.7f
    val hx = sin(t * 0.085f * 2f * PI + phw) * 2.6f + sin(t * 0.205f * 2f * PI + 1.7f) * 1.1f
    val hy = sin(t * 0.072f * 2f * PI + 0.6f + phw) * 2.2f + sin(t * 0.178f * 2f * PI + 2.3f) * 0.9f
    val rot = sin(t * 0.055f * 2f * PI + 2.1f + phw) * 0.12f + (p - 0.5f) * 0.22f
    val breathe = 1f + sin(t * 0.13f * 2f * PI + 0.9f) * 0.0032f

    return Cam(tx + hx, ty + hy, k * breathe, rot)   // tx,ty پیکسل · k مقیاس · rot درجه
}
```

**قانونِ دوربین (ایجبارى، برای همهٔ فیلم‌ها):**

> هر پلیتی که بیش از ~۵ ثانیه روی صفحه می‌ماند نباید ثابت بماند و نباید حرکتش را در مرزِ زیرنویس‌ها از نو شروع کند. مسیرِ دوربین روی **کلِ صحنه** محاسبه می‌شود: زوم‌اینِ آرام ← رانشِ پیوسته به یک سمت ← زوم‌اوتِ ملایم.

پیامدِ فنی: `p` و `dur` باید از `sceneT0/sceneT1` بیایند، نه از `sentence.start/end`. اگر حرکت را به جمله گره بزنی، همان باگِ «تکرارِ تصویر» برمی‌گردد.

### ۹٫۱ رندر روی GPU

- برای هر لایه یک texture: پلیت A/B، گرین، و «بیت‌مپِ متن/لوگو/کارت» که هر فریم با `Canvas` ساخته می‌شود.

## ۱۰. صفحات و UX (کمینه ولی کامل)

1. **پروژه‌ها** — لیست با کاور، مدت، وضعیت (پیش‌نویس/رندر‌شده).
2. **متن** — ادیتورِ فارسی؛ شمارشِ خط/کلمه؛ هشدارِ طولِ خط (بیش از ۲ خط)؛ دکمهٔ «شکستنِ هوشمند».
3. **صدا** — ایمپورت VO، موجِ صدا، پخش، «تحلیل» (ASR) با پیشرفت، دکمهٔ لغو.
4. **تصاویر** — ایمپورت چندتایی/تولید با API؛ پیش‌نمایشِ ۹:۱۶؛ برچسبِ «آماده» پس از پیش‌پردازش؛ امکان جای‌گذاریِ مجدد.
5. **چیدمان** — جدولِ خط‌ها؛ برای هر بازهٔ خط، یک پلیت + پریستِ حرکت + اسلایدرهای `amt/warm/fog` + دو نقطهٔ `a0/a1`. دکمهٔ «چیدمانِ خودکار» (یک صحنه به‌ازای هر ۱–۲ خط، ۵ تا ۱۲ ثانیه، بدونِ تکرار).
6. **استایل** — پریستِ `odd-file-story` (همین اعداد)، ویرایشِ لوگو/شفافیت/فاصلهٔ زیرنویس؛ پیش‌نمایشِ زندهٔ یک فریم.
7. **پایان** — عکسِ واقعی + سه خطِ متن + انتخابِ لحظهٔ شروع (پیش‌فرض: خطِ CTA).
8. **رندر** — دکمهٔ بزرگ، تخمینِ زمان، پیشرفت، لغو، «ذخیره در گالری»، «اشتراک».
9. **بازبینی** — کانتکت‌شیتِ ۱۲ فریم + گزارشِ هم‌ترازی (بیشترین انحراف، تعدادِ کلمه‌های مشکوک) + پخشِ نهایی.

قاعده‌های UX: هیچ تنظیمی که در فیلمِ مرجع اثر ندارد اضافه نشود؛ پیش‌فرض‌ها همان مقادیرِ مرجع؛ هر تغییر در پیش‌نمایش فوری دیده شود.

---

## ۱۱. کارایی، فایل، مجوزها

- رمزِ موفقیت: کش. پلیت‌های پیش‌پردازش‌شده، نتیجهٔ ASR، بیت‌مپِ متن‌ها و قطعه‌های رندرشده همه کش شوند.
- حافظهٔ هدف: < ۴۰۰MB هنگامِ رندر (پلیت‌ها با `BitmapFactory.inSampleSize` در اندازهٔ لازم، نه اصلی).
- مجوزها: `READ_MEDIA_IMAGES`/`READ_MEDIA_AUDIO` (یا Photo Picker بدونِ مجوز)، `FOREGROUND_SERVICE_MEDIA_PROCESSING`، `POST_NOTIFICATIONS`. ذخیره با MediaStore (بدونِ `WRITE_EXTERNAL_STORAGE` روی ۲۹+).
- فونت‌ها و لوگو داخلِ assets؛ هیچ دانلودِ فونت در زمانِ رندر.

## ۱۲. پذیرش (Definition of Done)

با «پروژهٔ مرجع» (همان ۴۷ خط، همان VO، همان ۳۲ پلیت، همان `SCENE_OF`) خروجیِ اپ باید:

1. طول = ۲۱۱٫۲۶ ثانیه ± ۱ فریم؛ ۶۳۳۸ فریم؛ ۱۰۸۰×۱۹۲۰؛ ۳۰fps. ✅
2. SSIMِ فریم‌های نمونه (۰، ۵۰۰، ۱۵۰۰، ۳۰۰۰، ۴۵۰۰، ۶۰۰۰) در برابرِ فیلمِ مرجع ≥ ۰٫۹۵. ✅
3. میانهٔ انحرافِ زمانیِ کلمه‌ها ≤ ۵۰ms؛ هیچ کلمه‌ای > ۱۵۰ms. ✅
4. لوگو: عرض ۱۹۰px، شفافیت ۰٫۳۰، مرکزِ افقی، `bottom` ۱۹۶px، هیچ‌جا پوشیده نشود (شاملِ کارتِ پایانی). ✅
5. زیرنویس: در ۴۷۰px از پایین، بالای ناحیهٔ UI ریلز؛ کلمهٔ فعال طلایی و کمی بزرگ‌تر. ✅
6. بدونِ گریدِ تیره/وینیت؛ تنها تاریکیِ موضعی زیرِ زیرنویس و پردهٔ کارت. ✅
7. کارتِ پایانی از ۲۰۰٫۷۴ ثانیه، با عکسِ واقعی و سه خطِ متن. ✅
8. رندر دوباره از صفر، همان فایل را بیت‌به‌بیت بدهد (determinism). ✅
9. قطعِ رندر در میانه و ادامهٔ آن، فایلِ سالم بدهد. ✅
10. اندازهٔ فایلِ ۳:۳۱ بین ۸۰ و ۱۰۰ مگابایت. ✅

## ۱۳. نقشهٔ راه (ترتیبِ ساخت)

- **M0 — اسکلت**: پروژهٔ Compose، Room، ایمپورتِ پروژهٔ JSONِ مرجع (script/scenes/sceneOf/words)، صفحهٔ لیست.
- **M1 — پخش‌کنندهٔ دقیق**: `renderFrame(t)` در GPU با پلیت + دوربین + گذار؛ تست‌های طلاییِ ۶٫۴.
- **M2 — زیرنویس**: تایپوگرافی Vazirmatn، انیمیشنِ کلمه، اسکریم؛ مقایسه با فریم‌های مرجع.
- **M3 — صدا و هم‌ترازی**: دیکد VO، ASR داخلی، DP، صفحهٔ ویرایشِ دستی، کش.
- **M4 — خروجی**: MediaCodec + MediaMuxer + AAC؛ رندرِ کاملِ پروژهٔ مرجع و رسیدن به معیارهای ۱–۳.
- **M5 — کارتِ پایانی، لوگو، استایل، چیدمانِ خودکار**.
- **M6 — مقاوم‌سازی**: ادامه‌پذیری، حرارت، نوتیفیکیشن، اشتراک، گزارشِ QA.

هر مرحله باید یک خروجیِ قابلِ دیدن داشته باشد (اسکرین‌شات/ویدیو)، نه فقط کد.

## ۱۴. نبایدها (اگر این‌ها را انجام دهی، تحویل رد است)

- حرکتِ دوربین بر اساسِ هر جمله (ریست در مرزِ زیرنویس). باید بر اساسِ صحنه باشد.
- افزودنِ وینیت/گرادیانِ تیره/تیترِ ابتدایی/افکتِ گذارِ دیگر (فقط دیزالو ۰٫۵ ثانیه + افتِ روشناییِ ۰٫۲۲).
- تغییرِ کلماتِ متنِ کاربر یا ترجمه/بازنویسی؛ فقط شکستنِ خط.
- زیرنویس با timing تخمینی یکنواخت؛ ممنوع. باید از صدا استخراج شود.
- قاب/پیل/بلور/حاشیه دورِ لوگو.
- ذخیرهٔ فریم‌ها روی دیسک در مسیرِ رندرِ نهایی.
- دانلودِ فونت/لوگو/مدلِ ASR در لحظهٔ رندر بدونِ کش.
- هر انیمیشنی که به `System.currentTimeMillis()` یا `Random` وابسته باشد.

## ۱۵. آنچه باید اول از من بپرسی

اگر در جایی از این سند ابهام بود، **قبل از کدنویسی** این‌ها را بپرس:

1. ASR روی گوشی (دقیق، آفلاین، +۱۵۰MB) یا ابری (سریع، نیازمندِ شبکه)؟
2. تولیدِ تصویر داخلِ اپ (کلیدِ API) یا فقط ایمپورت از گالری؟
3. حداقلِ نسخهٔ اندرویدِ هدف و گوشیِ مرجع برای تستِ کارایی.
4. آیا باید پریست‌های استایلِ دیگرِ همین ریپو (odd-file، kamand-vox) هم در اپ باشد یا فقط استایلِ «فیلمِ داستانی»؟
